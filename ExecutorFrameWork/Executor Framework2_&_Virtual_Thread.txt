 Fork Join Pool Executor
 
 parallelism - task divided into multiple subtasks and each task executed independently and then join the result.
 
 we have thread pool and submission queue as well in it
 
 each thread has its own private queue.
 
 +-----------------------------+
                      |    Global Submission Queue  |
                      |  [Task 1][Task 2][Task 3]   |
                      +--------------+--------------+
                                     |
                +--------------------+--------------------+
                |                                         |
                v                                         v
   +-------------------------+               +-------------------------+
   |        THREAD 1         |               |        THREAD 2         |
   |  (Pulls / Pop from Top) |               |  (Pulls / Pop from Top) |
   +------------+------------+               +------------+------------+
                |                                         |
                v                                         v
   +-------------------------+               +-------------------------+
   |   Work-Stealing Queue   |  <============|   Work-Stealing Queue   |
   |      (Deque 1)          |   STEAL TASK  |      (Deque 2)          |
   |                         |  (From Bottom)|                         |
   | +---------------------+ |==============>| +---------------------+ |
   | |  Task A             | |               | |  Task X             | |
   | +---------------------+ |               | +---------------------+ |
   | |  Task B             | |               | |  Task Y             | |
   | +---------------------+ |               | +---------------------+ |
   +-------------------------+               +-------------------------+
 
 
 A task comes up which is taken by thread 1 and divide that tasks into two tasks that is task1 and task2. Now task one taken by thread 1 and put the task 2 in its stealing queue. Then this task2 has been taken by thread 2 
 as it is idle.
 
 result of task1 and task2 has been combined.
 
 Fork join pool executor is only used for the task which we can divide it into sub tasks.
 
 ** Note -- Java parallel stream uses the fork join pool executor.
 
 
 Now if task3 comes up and both the threads are busy in executing the subtasks then task 3 has been added to the global queue. 
 
 
 If any sub task is available in the stealing queue and any pending task is available in the global queue, then idle thread will not take task from the stealing queue of another thread, it takes task from the global queue.
 But if the task is available in its own stealing queue, then it takes the task from its own queue.

Virtual Threads 

Whenever we create a thread, its been created in the JVM and it is directly linked to the operating system thread. whenever a thread is waiting or blocked that cant be used. Creating multiple threads increases the memory
and load on cpu.

Virtual Threads - Virtual Thread are the Java thread that are managed by the JVM, we can create millions of virtual thread. Until a task has been assigned, it is unlinked to the OS threads.

For example if thread 1 and thread 2 of the JVM is linked to the operating system thread 1 and thread 2. 

If the thread1 goes to the waiting or blockeds state, then another virtual thread in the jvm has been linked to this os thread and executes its task.

**Note - So basically in the virtual thread concept the OS thread acts as an thread pool.
 
 
 Its benefit is we can create millions of virtual threads.
 
 How many OS thread will be available -- depends on the cpu core. if the cpu core is 4, then 4 os threads , if 8 then 8 os threads.
